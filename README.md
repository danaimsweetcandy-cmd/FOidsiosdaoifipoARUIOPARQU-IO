# 가계부 PWA

쓰는 순간에 3탭으로 남기고, Google Sheets를 원본(canonical) 데이터로 삼아 여러 기기에서 자동으로 맞춰지는 개인 가계부.

## 파일

| 파일 | 역할 |
|---|---|
| `index.html`, `style.css`, `app.js` | 앱 본체 |
| `manifest.json`, `sw.js` | 홈화면 설치 + 오프라인 동작 |
| `icon-192.png`, `icon-512.png`, `icon-maskable.png` | 아이콘 |
| `Code.gs` | 구글시트에 붙일 Apps Script (앱과 함께 올리지 않아도 됨) |

## 1. GitHub Pages에 올리기

1. 새 저장소를 만든다 (셀프챗 때처럼 눈에 안 띄는 이름으로)
2. `Code.gs`와 `README.md`를 뺀 나머지 파일을 루트에 올린다
3. Settings > Pages > Source를 `Deploy from a branch`, 브랜치 `main` / `(root)`로 지정
4. 몇 분 뒤 `https://아이디.github.io/저장소이름/` 접속
5. 갤럭시 크롬에서 메뉴 > 홈 화면에 추가

이 단계까지만 해도 앱은 완전히 동작한다. 데이터는 휴대폰 안에만 저장된다.

## 2. 구글시트 연동 (여러 기기를 쓴다면 필수)

1. 새 구글 스프레드시트를 만든다
2. 확장 프로그램 > Apps Script > 기본 코드를 지우고 `Code.gs` 내용을 붙여넣는다
3. 맨 위 `TOKEN` 값을 아무도 모를 문자열로 바꾼다. (강력한 보안 비밀값일 필요는 없고, 공개된 웹앱 URL에 대한 무차별 접근을 막는 정도의 목적)
4. 함수 목록에서 `setup` 을 골라 실행 (첫 실행 때 권한 승인)
5. 배포 > 새 배포 > 유형 `웹 앱`
   - 실행 계정: **나**
   - 액세스 권한: **모든 사용자**
6. 나온 `.../exec` 주소를 앱 설정 화면의 `웹앱 주소`에, 3번의 토큰을 `토큰`에 넣는다
7. `연결 확인` 버튼으로 확인 (누르면 서버 최신 데이터를 실제로 받아온다)

시트에 `거래` / `월간요약` / `카테고리별` 세 탭이 생긴다. `Code.gs`를 고친 뒤에는 **배포 관리 > 편집 > 버전: 새 버전**으로 다시 배포해야 반영된다.

기존에 이 앱을 이미 쓰고 있었다면(구버전 시트), `setup`을 다시 실행하거나 앱에서 한 번 동기화하면 `거래` 시트에 `삭제` 컬럼이 자동으로 추가된다. 기존 데이터는 그대로 유지된다.

## 3. 쓰는 법

- **금액 → 분류 → 저장.** 소분류·메모·결제수단은 안 골라도 저장된다 (결제수단은 마지막에 쓴 게 자동 선택)
- 자주 쓰는 지출은 입력값을 채운 뒤 설정 > `지금 입력값을 추가` 로 원탭 버튼 등록
- 카테고리 순서는 많이 쓴 순으로 자동 정렬된다
- 지우기 키를 길게 누르면 금액이 한 번에 지워진다
- 내역에서 항목을 탭하면 수정/삭제
- 왼쪽 위 월 이름을 탭하면 다른 달로 이동
- 오른쪽 위 점: 초록 = 시트까지 동기화 완료, 노랑 = 올릴 게 남음, 빨강 = 전송 실패/토큰 오류

## 동기화 방식 (Google Sheets가 원본)

```
                 Google Sheets (원본)
                    ▲         ▼
                    │         │
             Google Apps Script
                    ▲         ▼
                    │         │
                   PWA  ──  localStorage(캐시/오프라인 버퍼)
```

- 모든 통신은 **GET + query string**이다 (`?action=...&token=...&payload=...`). POST는 쓰지 않는다 - Apps Script 웹앱의 내부 리다이렉트 과정에서 POST body가 사라지는 문제가 있었기 때문. `Code.gs`의 `doPost`는 호환용으로만 남아있고 실제 처리는 하지 않는다.
- 거래 하나가 대략 300~500바이트 정도라 GET 한 번에 최대 `GAS_CHUNK_SIZE`(기본 10)건씩 나눠 올린다. (URL 길이 제한 때문에 한 번에 너무 많이 보내지 않음)
- 저장 즉시 로컬(휴대폰/PC)에 반영되고, "저장할 때 바로 올리기"가 켜져 있으면 곧바로 시트에도 올라간다. 업로드에 성공하면 곧이어 서버 최신 데이터를 다시 받아와 화면을 맞춘다.
- **다음 시점마다 서버(Google Sheets)에서 최신 데이터를 자동으로 가져온다**: 앱 최초 실행, 온라인 복귀, 앱이 다시 포그라운드로 전환될 때, `동기화 상태` 점 클릭, 설정의 `지금 올리기` / `연결 확인` 버튼
- 같은 id의 거래가 로컬과 서버 양쪽에 있으면 `updated`가 더 큰(최신) 쪽이 승자가 된다. `Code.gs`도 동일한 기준으로, 서버에 이미 더 최신인 데이터가 있으면 오래된 업로드 요청을 무시한다.
- 삭제는 시트에서 행을 실제로 지우지 않고 **tombstone 방식**(`삭제` 컬럼 = `Y`)으로 표시한다. `getAll`은 삭제된 거래도 포함해서 반환하며, 다른 기기는 이를 보고 자기 local 캐시에서도 해당 거래를 제거한다. 화면·통계·CSV에는 삭제된 거래가 나타나지 않는다. (월간요약/카테고리별 시트의 집계 수식도 삭제된 행은 제외하고 계산한다)
- **서버 데이터가 비어 있다는 이유만으로 로컬 데이터를 자동으로 지우지 않는다.** 아직 서버에 못 올린 로컬 전용 데이터는 항상 보존되고, 온라인이 되면 업로드된다.
- 백업 파일(JSON) 불러오기로 추가된 거래는 `synced` 값을 무조건 신뢰하지 않고 미동기화로 표시한 뒤, 다음 동기화 때 서버와 다시 맞춘다.
- 로컬 데이터 초기화("기기에서 전부 지우기")는 이 기기의 localStorage만 지운다. 구글 시트의 데이터는 지워지지 않으며, 시트를 통째로 비우는 기능은 따로 제공하지 않는다.

## 알아둘 것

- 비행기 모드에서도 저장된다. 인터넷이 붙으면 밀린 것부터 자동으로 올라가고, 곧이어 서버 최신 데이터를 다시 받아온다
- 데이터는 브라우저 저장소(약 5MB)를 쓴다. 한 건이 200바이트 정도라 수만 건까지 여유가 있지만, 브라우저 데이터를 지우면 같이 사라지니 시트 연동이나 정기 백업을 권한다
- 웹앱 주소가 노출되면 토큰을 아는 사람만 쓸 수 있다. 토큰은 아무도 모를 값으로
- `수입 - 지출`만 계산한다. `이체`는 계좌 간 이동이라 어느 쪽 합계에도 잡히지 않는다

## 업데이트 후에도 변경이 안 보일 때
서비스 워커가 이전 버전을 캐시해두기 때문. `sw.js`의 `CACHE` 값을 파일 바꿀 때마다 새 값으로 올려서 업로드하면 강제로 갱신됨 (이번 업데이트에서 v1 → v2로 이미 올려둠). 그래도 안 보이면 브라우저에서 사이트 데이터/캐시를 한 번 지우고 다시 열기.
